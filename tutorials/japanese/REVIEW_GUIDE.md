# 日本語チュートリアルのレビュー観点（案）

この文書は日本語版のレビューで使う観点の提案です。手順や技術的な事実は実装と英語原文に照らして確認します。

- 読者が初めて使う用語は、その用語を使うコマンドや図より前に説明する。Athenz ドメインと Kubernetes ネームスペース、ログインするユーザーと OAuth クライアント・サービス ID を区別する。
- トークンごとに、誰が保持・発行・交換・検証するかを追えるようにする。HTTPS 接続を信頼するための CA 証明書と、トークンの署名を検証する公開鍵の役割を分けて書く。
- コマンドの前に目的と期待する結果を書く。意図的に失敗する手順は実行前に知らせ、想定される状態と後の解消手順を示す。
- アドレスは、それを使うブラウザー、AI クライアント、Gateway、ZTS、MCP サーバーの視点で説明する。
- 日本語として自然な表現を選び、用語とコンポーネント名を揃える。原文の技術的な意味、コマンド、設定値、出力例を変えない。
- 疑問メモ、環境固有のエラーログ、確認できていない成功結果を手順本文に残さない。未解決の点は PR の議論で扱う。
